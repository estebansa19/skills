### Investigation

**You own the answer.** Read-only: the deliverable is a cited explanation or a recommendation, not
a code change.

1. Run the `how` skill for how it works. For a why question, run the `why` skill too, in
   parallel.
2. "Should we do X or Y": Design It Twice. Compare whole options in a table, each with how it
   fails, then recommend one.
3. "Are we sure?": settle what can be run by running it (Measure the Number), then give your real
   judgment with reasons. Push back when the premise is wrong.
4. Label the Evidence throughout.

If the answer turns into a change, finish the answer first, then switch to the change or bug-fix
playbook.

**Reply:** the answer itself (how's sections, or the recommendation and its table), with what is
still unknown.
